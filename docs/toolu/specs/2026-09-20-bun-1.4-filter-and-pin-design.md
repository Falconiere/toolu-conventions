# Bun 1.4 filter order and version pin — Design

**Date:** 2026-09-20   **Status:** Approved   **Author:** agent   **Topic:** Fix generated Bun 1.4 gate breakage (#30, #31)

## Problem

Projects generated by `@toolu/create` 0.9.0 fail on Bun 1.4 in two coupled ways:

1. **Filter argument order (#30).** Fan-out commands use `bun --filter '*' run <script>`. Bun 1.4 treats `run` as the script name (`Script "run" not found`), so root scripts, lefthook pre-commit, and CI gate steps fail before any package runs. The working form is `bun run --filter '*' <script>` (also valid on Bun 1.3).
2. **Version pin (#31).** Generated workflows pin `bun-version: 1.3.14`. A developer on Bun 1.4 writes `bun.lock` with `lockfileVersion: 2`, which 1.3.14 cannot parse, so the first CI install fails under `--frozen-lockfile`.

Observed on `agavus.io` (Bun 1.4.2). Issues #32–#34 (oxfmtignore / gitignore / lefthook format) are explicitly out of scope for this PR.

## Non-Goals

1. Do not change `.oxfmtignore`, `.gitignore`, or lefthook `format` job behavior (#32–#34; separate PR).
2. Do not bump this repository's root `@types/bun` / `bun-types` dependency (Jev: out of scope for the generated-consumer pin).
3. Do not introduce a runtime version gate or dual-command shims; one form must work on 1.3 and 1.4.
4. Do not rewrite historical design prose that merely mentions `bun --filter` as a concept, except where it teaches the broken `bun --filter … run …` invocation or breaks a living check.
5. Do not change non-filter Bun CLI usage unrelated to workspace fan-out.

## Architecture

**Filter form.** Replace every executable / taught fan-out of the shape `bun --filter <filter> run <script>` with `bun run --filter <filter> <script>`. Comments that say “fans out with `bun --filter`” may keep the conceptual phrase; runnable examples and CI/lefthook/`package.json` scripts must use the `bun run --filter` order. Align `shared/workspace/*` templates with the already-correct forms in `src/recipes.ts` monorepo package script emitters (~1390, ~2270).

**Pin.** Raise every generated / template `bun-version: 1.3.14` and Expo `eas.json` `"bun": "1.3.14"` to **1.4.2** (matches the reproducing developer Bun and issue guidance). Keep Expo CI comment “keep in sync with eas.json `bun`”. Also bump this kit’s own `.github/workflows/{ci,release}.yml` pins so the generator repo can install a lockfileVersion-2 `bun.lock` on the same CI image family.

**Decisive trade-off.** One PR for #30+#31 (shared CI/templates touch `shared/workspace/ci.yml` and `recipes.ts`) rather than splitting pins from filter order. Ignore-file work waits for a follow-up PR after merge + rebase.

## Interfaces / Schema

| Surface | Before | After |
|---|---|---|
| Root / workspace scripts | `bun --filter '*' run <script>` | `bun run --filter '*' <script>` |
| Lefthook lint job | `bun --filter '*' run lint` | `bun run --filter '*' lint` |
| CI gate steps (shared + inlined recipes) | same broken form | `bun run --filter '*' <script>` |
| Dev recipe (`recipes.ts`) | `bun --filter <pkg> run dev` | `bun run --filter <pkg> dev` |
| `setup-bun` / EAS | `1.3.14` | `1.4.2` |
| Historical plan check | `grep -q 'bun --filter' CORE.md` | still matches `bun run --filter` **or** update to `bun run --filter` explicitly |

Paths (authoritative edit set):

- `shared/workspace/{package.json,lefthook.yml,ci.yml}`
- `src/recipes.ts` (dev recipe + inlined CI template strings)
- Stack / convention workflow templates under `stacks/*/templates/.github/workflows/`, `conventions/cloudflare-infra/templates/.github/workflows/`
- `stacks/expo/templates/eas.json`
- Docs / templates teaching the broken form: `CORE.md`, `guardrails/README.md`, `stacks/database-ts/{SETUP,STRUCTURE}.md`, `**/AGENTS.md.template` as listed in #30
- Kit CI: `.github/workflows/ci.yml`, `.github/workflows/release.yml`
- Plan assertion if needed: `docs/toolu/plans/2026-08-06-database-ts-monorepo.md`

## Failure modes and edge cases

| Case | Observable behavior |
|---|---|
| Bun 1.4 + old filter order | `Script "run" not found` — must not appear after fix |
| Bun 1.3 + new filter order | Fan-out still resolves package scripts (no version gate). Verification is non-blocking when a Bun 1.3.x binary is unavailable on the agent host; the form is the documented Bun workspace CLI and already used elsewhere in `src/recipes.ts`. |
| Bun 1.3.14 CI + lockfileVersion 2 | Install parse failure — must not appear with pin 1.4.2 |
| Docs still showing old order | Developers copy-paste breakage — docs in scope must be updated |
| Conceptual `bun --filter` in comments | Allowed; must not be a runnable `… run <script>` line |
| Single-app (non-workspace) recipes already on `bun run --filter` | Leave unchanged |

## Acceptance criteria

- **AC-1:** In `shared/workspace/package.json`, `lefthook.yml`, and `ci.yml`, no line matches the runnable pattern `bun --filter .* run `, and each file still contains at least one `bun run --filter` fan-out.
- **AC-2:** `src/recipes.ts` emits `bun run --filter` for the API `dev` recipe and for every inlined monorepo CI `run:` fan-out step, with zero remaining `bun --filter .* run ` matches in that file.
- **AC-3:** Every listed pin site that was `1.3.14` is `1.4.2`: `shared/workspace/ci.yml`, `src/recipes.ts` inlined CI, `stacks/{backend-ts,console,marketing,expo}/templates/.github/workflows/ci.yml`, `stacks/expo/templates/eas.json`, `conventions/cloudflare-infra/templates/.github/workflows/deploy-{development,production}.yml`, and kit `.github/workflows/{ci,release}.yml`. Root `@types/bun` may remain `1.3.14`.
- **AC-4:** `CORE.md`, `guardrails/README.md`, `stacks/database-ts/SETUP.md`, `stacks/database-ts/STRUCTURE.md`, `shared/packages/ui/templates/AGENTS.md.template`, `shared/packages/types/templates/AGENTS.md.template`, and `stacks/database-ts/templates/AGENTS.md.template` that previously showed `bun --filter '*' run` now teach `bun run --filter '*' <script>` (at least one positive example on each surface that previously had a runnable example).
- **AC-5:** Under the machine’s Bun 1.4.2, a temporary two-package Bun workspace whose root scripts are copied from the updated `shared/workspace/package.json` fan-out lines runs `bun run lint` successfully without printing `Script "run" not found` (packages may use a trivial `lint` script such as `true`).
- **AC-6:** The living plan check in `docs/toolu/plans/2026-08-06-database-ts-monorepo.md` still passes against the updated `CORE.md` (either because `bun --filter` remains as a substring of `bun run --filter`, or the grep is updated intentionally).
- **AC-7:** A real `bun.lock` with `"lockfileVersion": 2` installs cleanly with `bun install --frozen-lockfile` when the active Bun is 1.4.2 (proves the pin target can read what Bun 1.4 writers produce). Fixture: copy or generate a lockfileVersion-2 lockfile into a temp dir (e.g. from a `bun install` under 1.4.2 in an empty package, or a checked-in fixture under `tests/fixtures/` if added by the plan).
