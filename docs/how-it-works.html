— toolu-conventions · in motion

The same rules, watched running.

The written guide says what the kit enforces. This page shows it happening: the scaffold run, the tree it produces, the fourteen structure checks, the hooks that fire while an agent types, the CI gate on a pull request, and the motion rules the UI itself obeys.

Every diagram animates once when it scrolls into view and can be replayed. Motion here follows the kit's own rule — it measures, it never performs: one easing curve, no bounce, no shimmer, no spin. With prefers-reduced-motion: reduce set, each diagram renders as a finished run instead.

— §01 · the scaffold run

One entry point, one dispatch.

There is no CLI and no generator. A coding agent is pointed at SETUP.md, which checks prerequisites, asks the intake questions, and dispatches to exactly one stack. From there it copies that stack's templates and inherits CORE.md — the rules every stack shares.

— §02 · folder structure

The tree is a config, not a habit.

guardrails.config.json names the only directories allowed under src, and the only subdirectories allowed inside each domain. A folder nobody sanctioned is a failing check, not a code-review opinion.

— §03 · agent-guardrails

Fourteen checks, one owner each.

One shared shell module, copied into every project as scripts/guardrails/run.sh and driven by guardrails.config.json. It enforces the structure — the tree, colocated tests, barrels, banned dependencies, required files, shadowing configs, committed secrets — both tracked secret files and credential shapes inside tracked content — and contextual code patterns via ast-grep, plus directives that suppress dead-code enforcement. Anything oxlint, oxfmt, clippy or rustfmt already enforces stays with them: two enforcers of one rule is how ceilings drift apart. That is why half the run below stands down — on a TypeScript stack those ids are declared ownedByLinter and oxlint reports them instead. On Rust, where oxlint cannot parse the source at all, every one of the fourteen runs here.

A check id is the unit of ownership. ownedByLinter names ids, and naming one skips the whole check — which is why the README and test-tree rules are their own ids rather than riding along inside folder-tree and colocated-tests. Bundled, declaring the parent linter-owned would have switched them off in the shell module while nothing in the plugin ever picked them up.

— §04 · hooks

Same module, three moments.

The runner has one body and several entrances. An agent hook reports in milliseconds on the file just written; a Stop hook re-runs the whole repo and refuses to let the turn end red; Lefthook runs it over staged files before a commit lands. Each entrance catches a mistake earlier than the next, and none replaces another — the agent hooks only ever fire for agents.

— §05 · ci / cd

The gate runs twice: locally, then in the open.

bun run check is the command before a push; CI mirrors those steps by name and then proves the production build, so a green terminal and a green pull request mean the same thing — each step separate, so a red run names the gate that failed instead of burying it in one aggregate command. Alongside it, an AI reviewer reads the repo's own convention files from the base branch — a pull request cannot rewrite the rules it is judged by.

— §06 · design

Motion measures; it never performs.

The design language ships as tokens — theme/scale.css and theme/palette.css on the web stacks, theme/motion.ts and theme/colors.ts on Expo — and the rules about what may move at all. One easing curve, five durations, and a tactile vocabulary that ends at a 1px nudge. This page is built from the same tokens, so what you are reading is what a scaffolded project gets.

— §07 · where a mistake gets caught

Five layers, earliest wins.

The layers are ordered by how early they catch a mistake, because the earliest is the cheapest to fix. Take a real one: an agent adds a vitest.config.ts to get its tests running. It looks harmless, and it silently replaces vite.config.ts under test — the router plugin and the @/* alias vanish. The shadow-configs check knows that, and the agent's own turn ends on it. None of these layers may be disabled to get a green build: fix the check, or change the check deliberately and say so.
