## Quick start

```bash
bun install                    # install deps
cp .dev.vars.example .dev.vars # then fill in the secrets
bun run dev                    # wrangler dev — the real runtime, on :8787
curl localhost:8787/health     # → {"status":"ok"}
```

`bun` is the package manager. The **runtime is workerd** — `wrangler dev` runs
the same engine Cloudflare runs, so what passes locally is what deploys.

## Project layout

| Path | What |
| --- | --- |
| `src/app.ts` | The Hono app — routes + middleware mounted here (wiring only). |
| `src/index.ts` | Worker entry — `export default app`. The one default export. |
| `src/rpc/` | The typed API surface — oRPC procedures (`base.ts`, `router.ts`, `*-procedures.ts`). |
| `src/routes/` | Plain HTTP only: `/health`, webhooks, auth callbacks. |
| `src/services/` | Business logic — framework-agnostic, testable. |
| `src/utilities/` | Shared pure helpers. |
| `src/constants/` | `env.ts` (Zod-validated bindings) + enums. |
| `src/types/` | Cross-cutting types. |
| `wrangler.jsonc` | Worker config: name, entry, compat flags, vars, environments. |
| `worker-configuration.d.ts` | Generated by `wrangler types`. Committed; never hand-edited. |
| `.github/workflows/` | `ci.yml` (the gate) + `code-review.yml` (AI review). |

Every `src/*` folder has a `README.md` describing its contents.

## Configuration

Two homes, and the split is a security boundary:

| Kind | Lives in | Committed |
| --- | --- | --- |
| Non-secret config | `vars` in `wrangler.jsonc` | yes |
| Secrets | `.dev.vars` locally, `wrangler secret put` deployed | **no** |

Both are read through `src/constants/env.ts`, which parses them with a Zod schema.

| Var | Purpose | Where |
| --- | --- | --- |
| `APP_ENV` | `development` \| `staging` \| `production` | `wrangler.jsonc` |
| `TURSO_DATABASE_URL` | Turso database URL | secret |
| `TURSO_AUTH_TOKEN` | Turso auth token | secret |

Adding one means declaring it, running `bun run cf-typegen`, and validating it in
`env.ts`. Each environment needs its own secrets
(`wrangler secret put X --env staging`).

## Scripts

| Script | Does |
| --- | --- |
| `bun run dev` | `wrangler dev` — the real runtime, on `:8787`. |
| `bun run deploy` | `wrangler deploy`. |
| `bun run cf-typegen` | Regenerates `worker-configuration.d.ts` from `wrangler.jsonc`. |
| `bun run check` | Full gate: type-check + lint + format-check + structure + unused + dupes + test. |
| `bun run type-check` | `tsc --noEmit` (strict). |
| `bun run lint` / `lint:fix` | oxlint. |
| `bun run fmt` / `fmt:check` | oxfmt. |
| `bun run check:structure` | Folder tree, wrangler config, banned deps, untracked secrets. |
| `bun run check:unused` | knip — unused files, exports, dependencies. |
| `bun run check:dupes` | jscpd — copy-paste detection. |
| `bun run test` / `test:watch` | Vitest, **inside workerd**, against `wrangler.jsonc`. |

## Testing

Tests run in the real runtime through `@cloudflare/vitest-pool-workers`, using
this project's `wrangler.jsonc` and `.dev.vars`. They hit a real Turso database
— point `.dev.vars` at a dev/test database, never production, and have each test
clean up its own rows.

## CI and review

- **`ci.yml`** — checks the committed Worker types are current, runs the whole
  gate, then a dry-run deploy that bundles the Worker without publishing.
- **`code-review.yml`** — AI review of every PR against this repo's own
  convention files (read from the base branch). Needs a `DEEPSEEK_API_KEY`
  repository secret.

Both should be required checks on `main`.

## Conventions

Strict TypeScript, no barrel files, named exports (except the Worker entry),
kebab-case filenames, thin routes + services for logic, colocated real-data
tests, Zod at every boundary with types from `z.infer`. Full rules in
[`CLAUDE.md`](./CLAUDE.md).
