# Project Structure & Conventions

The canonical layout every new console app in this kit produces. It inherits
every rule in [`../../CORE.md`](../../CORE.md) and adds the console-specific
rules below — it never relaxes a CORE rule. Designed for **clean feature
iteration** and **easy LLM traversal**: predictable folder names, a README in
every top-level source folder, no barrel files (every import points at the file
that holds the thing), and thin route files.

> **Console, not "web".** This stack builds the **authenticated product
> console** — the app behind the login. The public marketing site is a different
> stack ([`../marketing/`](../marketing/), Astro), because a content site and a
> stateful app want opposite defaults. If a page has to be crawlable and fast on
> first paint, it belongs in `marketing`, not here.

## Folder tree

```
<app>/
├── index.html                # Vite entry document (project ROOT, not src/)
├── src/
│   ├── main.tsx              # Browser entry: creates the router, mounts <RouterProvider>
│   ├── route-tree.gen.ts     # GENERATED by TanStack Router. Committed, never hand-edited
│   ├── app/                  # File-based ROUTES ONLY (thin, see "Routes")
│   │   ├── __root.tsx        # Root route: the shell every route renders inside
│   │   ├── index.tsx         # `/` — points at a feature screen
│   │   └── shifts.$id.tsx    # `/shifts/:id` — flat-file route naming
│   ├── ui/                   # Design system — primitives + theme + globals.css. README.md
│   │   ├── globals.css       # The one global stylesheet (band seam); imported by main.tsx
│   │   └── theme/            # colors.ts · spacing.ts · typography.ts · motion.ts · icons.ts
│   ├── features/             # One folder per feature. README.md
│   │   └── <feature>/
│   │       ├── screens/      # <name>-screen.tsx (rendered by src/app/ routes)
│   │       ├── components/   # feature-local components
│   │       ├── hooks/        # feature-local hooks
│   │       ├── api/          # feature-local clients/queries (optional)
│   │       ├── types.ts
│   │       └── __tests__/
│   ├── api/                  # Cross-feature data layer. README.md
│   │   ├── orpc.ts           # The typed API client + its TanStack Query bindings
│   │   ├── http-client.ts    # The one configured http instance (non-oRPC calls)
│   │   ├── clients/          # request fns for third-party APIs
│   │   └── queries/          # hooks shared by several features (optional)
│   ├── utilities/            # Shared pure helpers. README.md
│   │   └── http.ts           # THE HTTP client (fetch). No axios — see LIBRARIES.md
│   ├── providers/            # App-level context providers. README.md
│   ├── constants/            # env.ts (Zod-validated), enums
│   └── types/                # cross-cutting TS types
├── public/                   # static assets copied to the site root verbatim
├── docs/                     # design-language.md — house UI rules, read before UI work
├── scripts/                  # guardrails/run.sh — folder-tree half of the gate
├── vite.config.ts            # Vite + TanStack Router plugin + Vitest (ONE config, see below)
├── wrangler.jsonc            # Cloudflare Workers deploy config (static assets)
├── tsconfig.json             # strict + `@/*` path alias
├── vitest.setup.ts
├── .oxlintrc.json · .oxfmtrc.json · lefthook.yml · .gitattributes
├── .env.example
├── .github/workflows/        # ci.yml (the gate) + code-review.yml (AI review)
├── CLAUDE.md                 # agent rules + repo map (read first)
└── README.md                 # human + agent entry point
```

> Folder vocabulary (`ui`, `utilities`, `api`, `features`, `providers`) is
> intentional and shared across the stacks in this kit. Keep it.

## One Vite config, not two

`vite.config.ts` holds the build config **and** the Vitest `test` block. Do not
add a `vitest.config.ts`: Vitest *replaces* the Vite config with it rather than
merging, so the TanStack Router plugin and the `@/*` alias would silently vanish
under test and route imports would fail with a confusing resolution error.
`defineConfig` is imported from `vitest/config` so the `test` key is typed.
`scripts/guardrails/run.sh` fails the gate if a second config appears.

## Path aliases

Configured in `tsconfig.json` (`paths`) and resolved by `vite-tsconfig-paths` in
both the build and the tests. Always import via the alias — never deep relative
paths like `../../../ui`.

| Alias | Resolves to | Example import |
| --- | --- | --- |
| `@/*` | `src/*` | `import { colors } from '@/ui/theme/colors'` |
| `@/ui/*` | `src/ui/*` | `import { Button } from '@/ui/button'` |
| `@/features/*` | `src/features/*` | `import { HomeScreen } from '@/features/home/screens/home-screen'` |
| `@/api/*` | `src/api/*` | `import { fetchShifts } from '@/api/clients/shifts'` |
| `@/utilities/*` | `src/utilities/*` | `import { createHttpClient } from '@/utilities/http'` |
| `@/providers/*` | `src/providers/*` | `import { AppProviders } from '@/providers/app-providers'` |
| `@/constants/*` | `src/constants/*` | `import { APP_ENV } from '@/constants/env'` |
| `@/types/*` | `src/types/*` | `import type { Shift } from '@/types/shift'` |

One base mapping (`@/*` → `src/*`) covers them all; the sub-namespaces above are
the conventional shape, not separate config entries. Deep relative imports
(`../../…`) are a lint error (`no-restricted-imports`); use the alias.

## Hard conventions (console — added on top of CORE)

These extend the CORE rules and are **machine-enforced** by `.oxlintrc.json` and
`scripts/guardrails/run.sh` (both run by `bun run check`; Lefthook runs the
lint/format subset on staged files). Each convention below names its enforcer.
See [`templates/CLAUDE.md.template`](./templates/CLAUDE.md.template) for the full
blocked-patterns list.

1. **`src/app/` is routes only, and thin.** A file under `src/app/` declares a
   `Route` that maps a URL to a feature screen and configures the route (loader,
   guard, error component). No data transformation, no business logic, no markup
   beyond composition. (See "Routes".)
   _Enforced by:_ `no-restricted-imports` (only `src/app/` may import
   `@/features/*`, so feature logic can't leak into other layers) + review.
2. **Named exports everywhere — including routes.** TanStack Router route files
   export `const Route`, so unlike a framework that demands default exports, this
   stack has **no default-export carve-out at all**, and the CORE no-barrel rule
   applies here without exception.
   _Enforced by:_ `import/no-default-export` (on everywhere except
   `vite.config.ts`) and `guardrails` (no `index.ts`/`index.tsx` outside
   `src/app/`, where `index.tsx` is Router's name for a directory's `/` route).
3. **It is all client code.** There is no server/client component split: this is
   a single-page app served as static assets. Anything secret belongs in the API
   service, never in this bundle — every `VITE_*` var is public by construction.
   _Enforced by:_ review, plus `.env.example` saying so in the file itself.
4. **Filename ↔ content.** Kebab-case filenames named after what they export
   (`shift-card.tsx` → `ShiftCard`, `use-shifts.ts` → `useShifts`). One primary
   export per file. TanStack Router owns two names — `__root.tsx` and the
   generated `route-tree.gen.ts` — plus the `$param` and dotted segments in route
   filenames.
   _Enforced by:_ `unicorn/filename-case` (kebab-case; off under `src/app/`
   where the router owns the naming).
5. **Two call paths, no third.** Our own API goes through `orpc`
   (`src/api/orpc.ts`); everything else goes through the `http` client
   (`src/api/http-client.ts`, built on `src/utilities/http.ts`). No `axios`, and
   no bare `fetch` scattered through features — auth headers, base URL, timeouts
   and error shaping live in one place each.
   _Enforced by:_ `no-restricted-imports` (axios) + `guardrails` (fails
   if `axios` appears in `package.json`) + review for stray `fetch`.
6. **Zod at every boundary, types inferred from it.** Env, any response `http`
   parses, form schemas, anything read from storage. `type X = z.infer<typeof X>`
   — never a hand-written interface sitting beside a schema, because the two
   drift and the compiler cannot say which is right (CORE rule 13).
   _Enforced by:_ `no-restricted-imports` (competing validation libraries) +
   review.
7. **Nothing unused, nothing duplicated.** `knip` fails the gate on an unused
   file, export, or dependency; `jscpd` fails it on copy-paste. Both are part of
   `bun run check`, not optional extras.
   _Enforced by:_ `knip.json` and `.jscpd.json` (`threshold: 0` is what fails
   the gate; `exitCode: 1` covers the case where the threshold is later raised).
8. **Co-locate tests** in a sibling `__tests__/` folder (`button.tsx` →
   `__tests__/button.test.tsx`), and test with **real data** — exercise real
   inputs and real integration paths. A mock-only test that just proves a mock
   returns what it was told is banned; it hides integration breakage (CORE
   rule 6).
   _Enforced by:_ `guardrails` (no centralized test dirs; every
   `*.test.ts(x)` must sit in a sibling `__tests__/`) + the Vitest `include`
   pattern; real-data rule by review.
9. **No `any`**, **no `console.log` / `debugger`**, **`max-lines: 300`** per file
   (code lines; tests exempt) — the CORE rules.
   _Enforced by:_ `typescript/no-explicit-any`, `no-console`, `no-debugger`, and
   `max-lines` (`skipBlankLines` + `skipComments`, off for tests).
10. **Flat until it grows.** Keep a component/util as a single file until it passes
    ~300 lines or sprouts sub-parts, then promote it to a folder
    (`button/` with `button.tsx` + `button.module.css`).
    _Enforced by:_ `max-lines` forces the split; folder shape by review.

## Style baseline (UI defaults)

Default UI manners for every screen and primitive. They aren't all
lint-enforceable, so they live here as the agreed baseline — deviate only when
the design explicitly calls for it, and say so in a comment.

1. **Tokens, not literals.** Colors, spacing, radii, and type come from
   `src/ui/theme/*` — no hardcoded hex, no magic numbers. Prefer CSS Modules or
   plain CSS that references the token values over inline `style` objects.
2. **Compose the primitives.** Build screens from the `src/ui/*` primitives so
   typography, color, and interactive states stay consistent.
3. **Accessible by default.** Semantic HTML first; interactive elements are
   real `<button>` / `<a>` with labels; images carry `alt`; forms have labels.
   The `jsx-a11y` plugin flags the common misses.
4. **Navigate with `<Link>`.** Use TanStack Router's `<Link to="…">` for internal
   navigation — it is type-checked against the route tree, so a renamed route
   becomes a compile error instead of a 404. A raw `<a href>` is for external
   links only.

## Routes (TanStack Router, file-based)

Routes are generated from the filesystem. `vite.config.ts` points the plugin at
`src/app/` and writes the tree to `src/route-tree.gen.ts`:

```ts
tanstackRouter({
  target: 'react',
  autoCodeSplitting: true,
  routesDirectory: './src/app',
  generatedRouteTree: './src/route-tree.gen.ts',
});
```

The generated tree lives **outside** `routesDirectory` on purpose — inside it,
the generator would keep re-reading its own output as a route.

A route file is a thin mapping from URL → screen:

```tsx
// src/app/index.tsx  →  /
import { createFileRoute } from '@tanstack/react-router';
import { HomeScreen } from '@/features/home/screens/home-screen';

export const Route = createFileRoute('/')({
  component: HomeScreen,
});
```

Filename → URL, in the flat style: `shifts.tsx` → `/shifts`,
`shifts.index.tsx` → `/shifts/`, `shifts.$id.tsx` → `/shifts/:id`,
`_authed.settings.tsx` → `/settings` inside a pathless `_authed` layout route.
The root `src/app/__root.tsx` is the shell every route renders inside.

**Commit `src/route-tree.gen.ts`.** It is generated, but `tsc --noEmit` needs it
to exist on a fresh clone, before any build has run. It is committed, excluded
from lint/format, marked `linguist-generated` in `.gitattributes`, and excluded
from the AI review — never hand-edit it.

## The `api/` data layer

Two paths, and picking the right one is the whole decision:

| Calling… | Use | Why |
| --- | --- | --- |
| **our own API** | `orpc` (`src/api/orpc.ts`) | Types come from the server's own procedure declarations. A renamed field is a compile error here, not a runtime `undefined` in production. |
| **anything else** | `http` (`src/api/http-client.ts`) | Third-party APIs, downloads, probes. Validate the response with a Zod schema via `parse`. |

### Our API: oRPC + TanStack Query

`src/api/orpc.ts` builds the client once and wraps it with
`createTanstackQueryUtils`, giving every procedure `queryOptions`,
`mutationOptions` and `key` — shaped exactly like the server's router:

```ts
import { useMutation, useQuery, useQueryClient } from '@tanstack/react-query';
import { orpc } from '@/api/orpc';

export function useShifts(locationId: string) {
  return useQuery(orpc.shifts.list.queryOptions({ input: { locationId } }));
}

export function useCreateShift() {
  const queryClient = useQueryClient();
  return useMutation(
    orpc.shifts.create.mutationOptions({
      onSuccess: () => queryClient.invalidateQueries({ queryKey: orpc.shifts.key() }),
    }),
  );
}
```

**There is no query-key factory in this stack.** The key is derived from the
procedure path, so `orpc.shifts.key()` invalidates everything under `shifts.*`
and cannot drift from the queries it is meant to match. Hand-writing
`['shifts', 'list', locationId]` next to an oRPC call is a bug waiting to
happen — two places to keep in sync, and an invalidation that silently matches
nothing once they disagree.

Use the v5 object API only (`useQuery({ … })` / `queryOptions` /
`mutationOptions`). Prefer `isPending` over the old query `isLoading` naming
when reading session or query status.

Feature hooks like the two above live in `src/features/<feature>/hooks/` when
one feature owns them, or `src/api/queries/` when several do.

### Forms: TanStack Form + Zod

House default (CORE). Install `@tanstack/react-form` with the baseline deps.
Validate with Zod via Standard Schema — pass the schema in `validators` (for
example `validators: { onSubmit: ShiftForm }`). Do not add
`@tanstack/zod-form-adapter`. Full example: [`LIBRARIES.md`](./LIBRARIES.md).

### Everything else: the `http` client

Configure the instance once:

```ts
// src/api/http-client.ts
import { BASE_API_URL, REQUEST_TIMEOUT_MS } from '@/constants/env';
import { createHttpClient } from '@/utilities/http';

export const http = createHttpClient({
  baseUrl: BASE_API_URL,
  timeoutMs: REQUEST_TIMEOUT_MS,
});
```

Then per-resource request functions in `src/api/clients/`, each parsing its
response with a Zod schema — the client will not hand back a type it did not
validate:

```ts
// src/api/clients/exchange-rates.ts
import * as z from 'zod';
import { http } from '@/api/http-client';

const Rates = z.object({ base: z.string(), rates: z.record(z.string(), z.number()) });
export type Rates = z.infer<typeof Rates>;

export function fetchRates(base: string): Promise<Rates> {
  return http.get('/rates', { query: { base }, parse: (body) => Rates.parse(body) });
}
```

> Route-level data can also be loaded by a TanStack Router `loader`, which starts
> the fetch before the component renders. Use a loader for data the screen cannot
> paint without; use React Query for data that is refetched, polled, mutated, or
> shared across screens. Wiring the two together
> (`loader: () => queryClient.ensureQueryData(orpc.shifts.list.queryOptions(...))`)
> gives you both.

## LLM-indexability strategy

An agent should answer "where does X live / is there a util for Y already?"
without reading the whole tree. We get that from:

- **A README in every top-level source folder** (`src/ui`, `src/features`,
  `src/api`, `src/utilities`, `src/providers`). Each lists what belongs there,
  what's currently inside (one line each), and where NOT to put things. Use
  [`templates/folder-README.md`](./templates/folder-README.md).
- **`CLAUDE.md` at the root** as the map + rulebook, read first by agents.
- **No barrels + filename ↔ content** means grep for a symbol lands on its
  definition immediately.
- **The `@/` path alias** makes import sites self-describing
  (`@/utilities/format-money` tells you exactly where it is).

When you add a notable util/primitive/feature, add a one-line entry to that
folder's README so the index stays current.
